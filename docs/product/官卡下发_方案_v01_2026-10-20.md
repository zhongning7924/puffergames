# 官卡远端下发 · 操作说明 v01

> 面向：项目 owner / 运维操作者
> 目的：把 40 关官方关卡从「随包内置」改成「可由服务器下发」，并说清每一步怎么操作、出了问题怎么退。
> 相关代码：`src/level-source.js`（客户端）、`src/config.js`（端点配置）、`tools/export-levels.js`（导出器）、服务器 `/opt/zoo-rank/app.py`（`GET /v1/levels/official`）

---

## 一、改关卡的三条路

| 入口 | 能做什么 | 产出 | 适合 |
|---|---|---|---|
| **本地后台** `tools/level-admin/` | 可视化改 40 关任意一关（拖拽/属性/章王），一键发布 | 直接写服务器 | ✅ **推荐**，不发版、不碰代码 |
| 主菜单 → **造关师** | 编辑**单关**，玩家侧创作工具，有试解/难度读数 | 关卡码 `PG2…`（分享用短码） | 玩家自制关，不是官卡 |
| 改 `src/levels.js` + 导出脚本 | 批量/结构性改动（如整体重排 40 关） | `official-levels.vN.json` | 大改、需要跑难度模拟时 |

后两条是「改内置源码」，需要重新打包发版；**第一条才是「不发版改关」的正解** —— 服务端版本号 +1 即可，客户端下次启动自己拉。

> 后台的详细用法见 [第六章](#六后台工具可视化改关卡)。
> 后台是**本地**的（只监听 127.0.0.1），不是云端网页后台；想做多人协作/手机端改关才需要上云，那要另外做鉴权。

## 二、三层数据模型（理解这个才能理解为什么能「恢复原版」）

| 层 | 存哪 | 谁写 | 会不会被远端覆盖 |
|---|---|---|---|
| **内置 builtin** | 随包代码 `levels.js` | 开发者发版 | 不会（代码里的） |
| **原始副本 original** | 本地存储 `angryBirds_official_original` | 首启 / `BUILTIN_VERSION` 变化时落盘 | **绝不**（远端碰不到） |
| **活动副本 active** | 本地存储 `angryBirds_official_active` | 首启落内置；远端有新版本时被覆盖 | 会 |

玩家点「恢复原版」= 把 active 改回 original，并记下被拒版本号（`angryBirds_official_dismissed`），**同一版本不会在下次启动又被推回来**。

## 三、下发链路

```
改 levels.js
   ↓  node tools/export-levels.js --version 2
outputs/official-levels.v2.json   { version:2, data:[40×Level] }
   ↓  scp 到服务器（文件名固定）
/opt/zoo-rank/data/official-levels.json
   ↓  GET https://aiclub.hk.cn/puffer/api/v1/levels/official
客户端启动 checkRemote()  ← 按 version 比对，大才采纳
   ↓
替 game.levels + 落盘 active + 主菜单横幅「官卡玩法已更新」
```

服务端按 **mtime + size** 做进程内缓存，换文件即生效，**不需要重启服务**。

## 四、完整操作步骤

### 4.1 改关卡

只改 `src/levels.js`。改完必须过门：

```bash
cd /Users/zhongning/games/angry-birds
node tools/validate-levels.js        # 几何/星级门槛校验
node tools/level-sim.js              # 动态难度模拟（不加 STATIC=1 跑真模拟）
STATIC=1 node tools/level-sim.js     # 静态门（CI 用）
node tools/e2e-tests.js              # 逻辑回归
```

⚠️ **同时把 `src/level-source.js` 的 `BUILTIN_VERSION` +1**。
它的作用是：让老玩家本地的「原始副本」在新版本首次启动时刷新成新内置数据，否则「恢复原版」会恢复成旧关卡。

### 4.2 导出下发包

```bash
node tools/export-levels.js --version 2
# 产物：outputs/official-levels.v2.json
# 打印：版本号 / 关卡数 / 3星门槛和 / 用鸟分布 / 体积 / 下一步命令
```

- **version 必须是正整数，且大于客户端当前生效版本**。内置是 `BUILTIN_VERSION`（当前 1），所以**第一次正式下发用 2**，之后 3、4、5…
- 想审阅内容可加 `--pretty`（带缩进，体积约翻倍）。

### 4.3 上传

```bash
scp outputs/official-levels.v2.json root@43.142.39.49:/opt/zoo-rank/data/official-levels.json
```

注意：**目标文件名固定为 `official-levels.json`**（不要带版本号，服务端读的就是这个名）。

### 4.4 验证

```bash
# 看版本号与关卡数（浏览器/curl 均可，公开只读接口）
curl -s https://aiclub.hk.cn/puffer/api/v1/levels/official | head -c 120
```

正常应返回 `{"version":2,"data":[{"name":"第 1 关",...`。
客户端下次启动即生效：菜单顶部出现「官卡玩法已更新」横幅，两个按钮「恢复原版 / 知道了」。

### 4.5 回滚

| 想回到什么 | 怎么做 |
|---|---|
| 玩家自己回退 | 设置页「恢复原版官卡」或横幅「恢复原版」 |
| 全网停止下发 | `ssh … 'rm /opt/zoo-rank/data/official-levels.json'` → 接口立刻返回 `{version:0,data:null}`，客户端视为无新版，**已下发的客户端不受影响**（它们本地已有 active） |
| 全网停用该功能 | `src/config.js` 的 `LEVELS.remoteUrl` 置空串 → 发版 |

> 「删文件」只阻止**尚未更新**的客户端继续拉取；已经拉取过的客户端仍用本地 active 副本，直到玩家点「恢复原版」。

## 五、版本号规则（踩过坑，务必遵守）

1. **只增不减**。复用旧号 = 老客户端认为"已是最新"，不会更新。
2. **不要跳过太多**。版本号无上限，但将来排查时看着乱。
3. **内置版本与远端版本是两个号**：
   - `BUILTIN_VERSION`（代码常量）管「原始副本刷新」；
   - `payload.version`（JSON 里）管「远端更新判定」。
   - 二者独立。远端第一次下发用 2 即可，不必与内置号同步。
4. **用户拒绝过的版本不会重推**（`angryBirds_official_dismissed`）。所以「改了个小错想重发」必须**用新版本号**，不能覆盖同一个号。

### 5.1 发布记录（每发一版在这里补一行）

| 版本 | 日期 | 改了什么 | 备注 |
|---|---|---|---|
| v2 | 2026-10-20 | L1 加木制护棚（2 立柱 + 顶板）；L8 章王关加前挡石盾 | 后台首次真实发布，全链路验证用；解关实测 L1 2/3 鸟、L8 3/5 鸟（原基线 1/3、3/5，章王关难度未变） |

> 想撤销某一版：删服务器文件**不会**让已更新的客户端回退（它们本地已有 active 副本）。真正的回滚是**发一个更高版本号、内容为内置 40 关的包**。

## 六、后台工具（可视化改关卡）

不想碰代码时的入口。**本地后台**，只监听 `127.0.0.1`，不暴露公网、无需登录（本机即权限）。

```bash
node tools/level-admin/server.js
# 打开 http://127.0.0.1:7788
```

三栏布局：**左** 40 关列表（◆ 表示有章王，数字是 章鱼·方块 数）｜**中** 375×667 画布｜**右** 属性面板。

| 操作 | 怎么做 |
|---|---|
| 改某一关 | 左侧点关卡 → 画布上拖拽方块/章鱼/珍珠 → 右侧改数值 |
| 微调坐标 | 选中后按方向键 1px，Shift+方向键 10px；拖拽时按住 Alt 脱离 1px 吸附 |
| 加/删元素 | 画布上方「＋方块 / ＋章鱼 / ＋珍珠」，选中后「删除选中」或按 Delete |
| 改章节属性 | 右栏「关卡」段：名称 / 副标题 / 提示 / 弹道档位 |
| 改星级门槛 | 右栏三个数字，必须递增（发布前会卡） |
| 改用鸟序列 | 右栏文本框，逗号分隔，如 `normal,normal,dash,bomb` |
| 造章王 | 选中章鱼 → 勾「章王」→ 选风格（5 种）自动带出半径/HP/名字 |
| 存草稿 | 顶栏「保存草稿」→ 写 `outputs/official-levels.working.json`，不上线 |
| 发布 | 顶栏「发布到服务器」→ 版本号自动 +1 → scp → 回读校验 |
| 撤销线上改动 | 顶栏「回滚内置」→ 把 `src/levels.js` 原版 40 关作为**新版本**发布（版本号照旧 +1） |

**发布过程做了什么**：校验 40 关数据（每关至少 1 章鱼、有鸟序列、星级递增；方块尺寸为正）→ 读服务器当前版本取 `max(线上, 本地)+1` → 写 `outputs/official-levels.vN.json` → `scp` 上传 → 再 GET 一次确认线上版本就是 N。任一步失败就中止，不会发出半个版本。

**它不改 `src/levels.js`**，这是刻意的：内置关卡只用于「首次启动无网」兜底，线上以服务器 JSON 为准。改源码就得重新打包发版，跟「不发版改关」的目标相反。若想让内置基线也跟上，需要另外改源码并把 `BUILTIN_VERSION` +1。

后台的数据来源优先级：本地草稿 → 服务器线上版本 → 内置关卡。顶栏 chip 会显示当前是哪个，以及「本地 vX · 线上 vY」。

## 七、接口契约

```
GET https://aiclub.hk.cn/puffer/api/v1/levels/official
（公开只读，无需鉴权，无需登录）

200 {"version": 2, "data": [ Level, ... ]}     # 正常
200 {"version": 0, "data": null}               # 服务器没放文件（= 不下发）
500 {"error": "bad_levels_file", "msg": "..."} # 文件格式不对（客户端会拒绝采纳）
```

`Level` 单关结构 = `src/levels.js` 里的原始结构（`name / flavor / birds / trajectory / stars / pigs / blocks / pearls`）。
客户端只做**形状校验**：必须是数组、每关有 `birds` 和 `pigs` 数组；不合格整包丢弃，绝不污染本地。

## 八、排错

| 现象 | 原因 | 处理 |
|---|---|---|
| 传了文件但客户端没反应 | version 不大于当前生效版本 | 换更大的号 |
| 传了但接口还返回旧版本 | 文件名不对 / 没放对目录 | 必须是 `/opt/zoo-rank/data/official-levels.json` |
| 接口 500 `bad_levels_file` | JSON 缺 `version` 或 `data` 非数组 | 重新用 `export-levels.js` 导出，别手改 |
| 横幅出来但点了「恢复原版」下次又变回来 | 旧版本客户端（无 dismissed 逻辑） | 升级到含 `angryBirds_official_dismissed` 的版本 |
| 关卡数量不对 | 导出时 `levels.js` 本身就不是 40 关 | 看导出摘要里的「关卡数」 |
| 后台发布报「上传失败」 | scp 密钥/网络问题 | 文件已生成在 `outputs/`，可手动 `scp` 重传 |
| 后台发布成功但线上版本没变 | scp 落在错目录，或读的是旧文件 | `curl …/v1/levels/official` 看 version；确认目标路径 |
| 后台打不开（端口占用） | 7788 被占 | `PORT=7799 node tools/level-admin/server.js` |
